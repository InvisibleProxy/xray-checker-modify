---
title: Telegram-бот
description: Запуск уведомлений, отчетов speed-test и команд управления через Telegram
---

Xray Checker умеет отправлять отчеты speed-test и оповещения о недоступности нод в обычный чат Telegram или в топик группы. Все запросы к Telegram Bot API выполняются через локальные SOCKS-порты Xray, то есть бот использует любую доступную ноду из текущей подписки.

## Что умеет интеграция

- Отправлять отчет после ручного, планового или запущенного из Telegram speed-test.
- Подсвечивать проблемные результаты speed-test, если скорость ниже заданного порога.
- Оповещать о недоступности ноды после заданного количества неудачных проверок.
- Оповещать о восстановлении ноды.
- Показывать статусы нод командой `/status`.
- Показывать последние замеры скорости конкретной ноды командой `/speed`.
- Запускать speed-test из Telegram командой `/speedtest`. Команда доступна только администраторам.
- Открывать главное сообщение с inline-меню командой `/start` или `/menu`.

## Требования

1. У приложения должна быть рабочая подписка с хотя бы одной доступной нодой.
2. Xray Checker должен быть запущен в обычном режиме, не `RUN_ONCE=true`.
3. Бот должен быть создан через BotFather.
4. Если используется группа или топик, бот должен быть добавлен в этот чат.
5. Для команд управления нужно указать Telegram user ID администратора.

:::note
Telegram с хоста может быть недоступен напрямую. Это нормально: Xray Checker отправляет сообщения через локальные SOCKS inbound нод, например `127.0.0.1:10000`, `127.0.0.1:10001` и далее.
:::

## Быстрый запуск через Docker Compose

Скопируйте пример окружения:

```bash
cp .env.example .env
```

Минимальная конфигурация:

```env
PUBLIC_DOMAIN=status.example.com
ACME_EMAIL=admin@example.com

SUBSCRIPTION_URL=https://provider.example/sub#Public%20VPN%20Status

METRICS_USERNAME=admin
METRICS_PASSWORD=replace-with-a-long-random-password

PROXY_CHECK_METHOD=status
LOG_LEVEL=info
SPEED_TEST_URL=https://proof.ovh.net/files/10Mb.dat

TELEGRAM_ENABLED=true
TELEGRAM_BOT_TOKEN=123456:bot-token-from-botfather
TELEGRAM_CHAT_ID=-1001234567890
TELEGRAM_MESSAGE_THREAD_ID=42
TELEGRAM_ADMIN_IDS=123456789
```

Запустите сервис:

```bash
docker compose up -d --build
```

Админ-панель будет доступна локально:

```text
http://127.0.0.1:2112/admin
```

Если используется `docker-compose.yaml.example` из репозитория, публичный Caddy-прокси не публикует `/admin`, `/metrics` и приватные API наружу. Управление Telegram-настройками остается доступным только через локальный порт Xray Checker.

## Получение chat ID, topic ID и admin user ID

Если вы не знаете ID чата или топика:

1. Укажите `TELEGRAM_ENABLED=true` и `TELEGRAM_BOT_TOKEN` в `.env`.
2. Оставьте `TELEGRAM_CHAT_ID`, `TELEGRAM_MESSAGE_THREAD_ID` и `TELEGRAM_ADMIN_IDS` пустыми.
3. Перезапустите сервис.
4. Напишите боту в нужном чате или топике:

```text
/id
```

Бот ответит:

```text
Chat ID: -1001234567890
Topic ID: 42
User ID: 123456789
```

После этого заполните в `.env`:

- `TELEGRAM_CHAT_ID` — ID чата или группы.
- `TELEGRAM_MESSAGE_THREAD_ID` — ID топика, если сообщения нужно отправлять в конкретную тему.
- `TELEGRAM_ADMIN_IDS` — список Telegram user ID администраторов через запятую.

Перезапустите сервис и нажмите `Test` в админке. Тестовое сообщение уйдет в заданный чат или топик.

## Настройки в админ-панели

Блок `Telegram` находится на странице `/admin`.

| Поле | Описание |
| --- | --- |
| `Enabled` | Включает Telegram-интеграцию. |
| `Bot token`, `Chat`, `Topic`, `Admins` | Только статус, задано ли значение через env. Сами значения в веб-интерфейсе не показываются и не изменяются. |
| `Bot commands` | Включает polling команд `/status`, `/speed`, `/speedtest`, `/id`. |
| `Speed reports` | Включает отправку отчетов после speed-test. |
| `Report mode` | `Always` отправляет каждый отчет, `Only issues` отправляет только отчеты с ошибками или низкой скоростью, `Disabled` отключает отчеты. |
| `Low Mbps` | Порог низкой скорости. Если результат ниже порога, в отчете будет акцент `LOW`. |
| `Report rows` | Максимальное количество строк в блоках проблем и лучших результатов. |
| `Node down alerts` | Включает оповещения о недоступности нод. |
| `Availability check min` | Как часто анализировать результаты обычной проверки доступности нод для alert-логики. |
| `Failed checks` | Сколько последовательных неудачных проверок нужно для alert. Минимум `2`: первая проверка фиксирует offline-состояние, повторная подтверждает alert. |
| `Diagnostics refresh min` | Как часто обновлять TCP/Ping-диагностику уже недоступной ноды. |
| `Reminder schedule min` | Backoff-расписание повторных уведомлений в минутах, например `15,60,180,360,720`. |
| `Max reminder min` | Максимальный интервал повторных уведомлений после окончания расписания. |
| `Group offline reminders` | Объединяет несколько due-уведомлений о недоступных нодах в одно сообщение. |
| `Recovery alerts` | Отправлять сообщение, когда нода восстановилась. |
| `Muted` / `Scope: All Telegram` | Отключает для выбранных нод и speed-test reports, и availability down/recovery alerts. Сохраняется в `mutedNodeIds`. |
| `Muted` / `Scope: Availability alerts` | Отключает только down/recovery alerts и offline-блок в issues summary. Speed-test reports остаются включены. Сохраняется в `mutedAlertNodeIds`. |
| `Muted` / `Scope: Speed reports` | Отключает только строки этой ноды в speed-test reports. Down/recovery alerts остаются включены. Сохраняется в `mutedSpeedNodeIds`. |

Нечувствительные настройки сохраняются в:

```text
data/telegram_config.json
```

При Docker Compose этот файл хранится в volume `xray_data`.

Токен бота, chat ID, topic ID и admin user IDs задаются только через переменные окружения:

```env
TELEGRAM_BOT_TOKEN=123456:bot-token-from-botfather
TELEGRAM_CHAT_ID=-1001234567890
TELEGRAM_MESSAGE_THREAD_ID=42
TELEGRAM_ADMIN_IDS=123456789
```

## URL для speed-test

URL на странице `/admin` в блоке `Speed Test` задает адрес файла для ручного запуска через кнопку `Run Selected`.

Если нажать `Save Schedule`, текущий `Test URL` сохраняется в расписание и будет использоваться для плановых проверок.

Для отдельной ноды можно задать свой `Test URL`: выберите ровно одну ноду в таблице `/admin`, заполните `Selected node URL` и нажмите `Save Node URL`. Такой URL имеет приоритет над глобальным `Test URL` и URL из расписания для этой конкретной ноды.

Для значения по умолчанию задайте переменную окружения:

```env
SPEED_TEST_URL=https://proof.ovh.net/files/10Mb.dat
```

Это значение используется как default для ручных проверок, расписания без сохраненного URL и запусков из Telegram. Если в расписании уже сохранен другой `Test URL`, он имеет приоритет над `SPEED_TEST_URL`.

## Команды бота

### Проверка ID

```text
/id
```

Показывает `Chat ID`, `Topic ID` и `User ID`. Команда полезна при первичной настройке.

### Справка

```text
/help
```

Показывает доступные команды.

### Меню

```text
/start
/menu
```

Открывает главное сообщение с кнопками: список нод, проблемные ноды, последние замеры и запуск speed-test для администратора. При навигации по кнопкам бот редактирует это же сообщение, а не отправляет новое. Повторный `/start` или `/menu` обновляет запомненное меню для текущего чата, топика и пользователя; после рестарта процесса первый вызов создаст новое меню.

Раздел `Ноды` показывает каждую ноду отдельной кнопкой. В карточке ноды видны текущий статус, latency, протокол, подписка, сервер и последние замеры. Администратор может запустить speed-test конкретной ноды прямо из этой карточки.

Speed-test отчеты отправляются с кнопкой `Меню`, чтобы после отчета можно было сразу вернуть главное меню в текущем сообщении.

### Статусы нод

```text
/status
```

Показывает количество online/offline нод и список нод со стабильными ID. Эти ID можно использовать в командах `/speed` и `/speedtest`.

### Последние замеры скорости ноды

```text
/speed <stableId или часть имени>
```

Примеры:

```text
/speed a1b2c3d4
/speed Germany
```

Команда показывает последние speed-test результаты выбранной ноды. Если скорость ниже порога `Low Mbps`, строка будет отмечена как `LOW`.

В web UI история доступна в `/admin` на вкладке `Speed History`: выберите ноду в списке `Node`, чтобы увидеть сохраненные замеры этой ноды.

Вкладка `/admin` → `Nodes Overview` показывает активные и архивные ноды. Если нода исчезла из подписки, она помечается как `Retired`, но сохраненные speed-test результаты остаются доступны для сравнения. В таблице можно фильтровать и сортировать ноды по средней, минимальной и максимальной скорости, числу ошибок, времени простоя, последнему появлению, подписке и стране из имени ноды.

Архивную `Retired` ноду можно удалить из `Nodes Overview` после подтверждения. Активные ноды удалять нельзя: они управляются текущей подпиской и снова появятся при следующем обновлении подписки.

Последние результаты и история speed-test сохраняются в:

```text
data/speedtest_results.json
```

Архив нод, агрегаты простоя и Geo/IPInfo cache сохраняются в:

```text
data/node_registry.json
```

Количество сохраняемых замеров для каждой ноды задается в `/admin` полем `Results per node` и сохраняется через `Save Schedule`. По умолчанию хранится 10 последних результатов на ноду.

Страна ноды определяется по флагу, названию страны или коду страны в имени. Фактическая страна IP не запрашивается автоматически при открытии страницы: используйте кнопку `Refresh Geo` во вкладке `Nodes Overview`, чтобы обновить cache через IPInfo. Клик по IP/адресу ноды открывает страницу IPInfo в новой вкладке.

При Docker Compose этот файл хранится в volume `xray_data`, поэтому замеры доступны после перезапуска контейнера.

### Запуск speed-test

Запуск проверки скорости для online-нод:

```text
/speedtest
```

Запуск проверки скорости для всех нод:

```text
/speedtest all
```

Запуск проверки скорости одной ноды:

```text
/speedtest a1b2c3d4
/speedtest Germany
```

Фильтрация по протоколу:

```text
/speedtest protocol:vless
```

Фильтрация по подписке:

```text
/speedtest sub:Premium
```

Команда `/speedtest` доступна только пользователям из `TELEGRAM_ADMIN_IDS`.

## Как выбирается нода для Telegram

Для отправки сообщения Xray Checker:

1. Берет текущий список прокси.
2. Проверяет текущие метрики доступности.
3. Выбирает online-ноды и сортирует их по меньшей задержке.
4. Пробует отправить запрос к Telegram Bot API через локальный SOCKS-порт выбранной ноды.
5. Если запрос не удался, пробует следующую доступную ноду.

Если статусы еще не известны, сервис пробует использовать ноды из конфигурации. После первой проверки доступности выбор становится точнее.

Если все ноды недоступны, отправить сообщение в Telegram невозможно: у приложения нет прямого fallback-подключения к Telegram.

## Рекомендуемый порядок запуска

1. Запустите Xray Checker с подпиской.
2. Дождитесь первой проверки нод или нажмите refresh в админке.
3. Создайте бота через BotFather.
4. Добавьте бота в чат или топик.
5. Укажите `TELEGRAM_BOT_TOKEN` в `.env`, включите `TELEGRAM_ENABLED=true` и перезапустите сервис.
6. Получите ID через `/id`.
7. Заполните `TELEGRAM_CHAT_ID`, `TELEGRAM_MESSAGE_THREAD_ID` и `TELEGRAM_ADMIN_IDS` в `.env`.
8. Перезапустите сервис и нажмите `Test`.
9. Настройте `Low Mbps`, режим отчетов и параметры down-alert в `/admin`.

## Диагностика

### Бот не отвечает на `/id`

Проверьте:

- `Enabled` включен.
- `TELEGRAM_BOT_TOKEN` задан верно.
- `Bot commands` включены.
- В подписке есть хотя бы одна нода, через которую доступен Telegram.
- Бот добавлен в нужную группу или топик.

### Test message не отправляется

Проверьте:

- `TELEGRAM_CHAT_ID` заполнен.
- `TELEGRAM_MESSAGE_THREAD_ID` указан только если нужен конкретный топик.
- Бот имеет право писать в чат.
- После запуска уже появилась хотя бы одна рабочая нода.

### Отчеты speed-test не приходят

Проверьте:

- `Speed reports` включен.
- `Report mode` не равен `Disabled`.
- При режиме `Only issues` есть ошибка или результат ниже `Low Mbps`.
- Speed-test действительно завершился.

### Alert о падении ноды не приходит

Проверьте:

- `Node down alerts` включен.
- Нода провалила проверку минимум `Failed checks` раз подряд. Значение меньше `2` нормализуется до `2`, поэтому первый краткий провал только сохраняет состояние и диагностику.
- Для уже недоступной ноды наступило время `NextAlert` по `Reminder schedule min` / `Max reminder min`.
- Есть хотя бы одна другая доступная нода, через которую можно отправить сообщение в Telegram.
